# 🚀 Архитектурное решение (ADR) 0003: Проектирование CI/CD конвейера и сборки релизов

- **Статус**: Принято (Accepted)
- **Дата**: 2026-09-02 (Обновлено: 2026-09-08)
- **Область**: GitHub Actions, матричная кросс-компиляция, автотестирование, дистрибьюция через publish.py

---

## 📋 Контекст и проблематика

Лаунчер **Space Station 14** поставляется для трех операционных систем: Linux (x64, ARM64), Windows (x64, ARM64) и macOS (x64, ARM64).
Требования к процессу непрерывной интеграции и доставки (CI/CD):
1. **Предотвращение регрессий на всех целевых ОС**: ошибки кросс-платформенности должны обнаруживаться до слияния кода в `master`.
2. **Гарантия целостности дистрибутивов**: каждый релиз должен содержать готовые, полностью автономные архивы (self-contained) с встроенным рантаймом .NET 10, нативным загрузчиком и криптографическими контрольными суммами `SHA256SUMS.txt`.
3. **Безопасность зависимостей**: сканирование цепочки поставок NuGet и автоматический аудит уязвимостей в коде.

---

## 🎯 Принятые решения

### 1. Матричный конвейер сборки и тестирования (`build-test.yml`)
- **Триггеры**: Push в `master` и создание Pull Request в `master`.
- **Матрица окружений**:
  - `ubuntu-latest`
  - `windows-latest`
  - `macos-latest`
- **Шаги конвейера**:
  1. Клонирование репозитория со всеми вложенными подмодулями (`submodules: recursive`).
  2. Инициализация .NET SDK 10.0.
  3. Кэширование пакетов NuGet по хэшам файлов `.csproj`.
  4. Проверка форматирования кода: `dotnet format --verify-no-changes`.
  5. Сборка решения в конфигурациях Debug и Release с флагом `-warnaserror:CS4014`.
  6. Прогон полного набора из 138 модульных тестов на каждой платформе.

### 2. Скрипт сборки и упаковки дистрибутивов (`publish.py`)
- **Решение**: Использовать стандартизированный скрипт `publish.py` на Python 3 для локальной и автоматической сборки дистрибутивов:
  - Автоматическая загрузка официального микро-рантайма Microsoft .NET 10 для платформ назначения (`download_net_runtime.py`).
  - Сборка с оптимизацией ILLink/Trimming для минимизации размера исполняемых файлов.
  - Настройка подсистем исполняемых файлов Windows (`exe_set_subsystem.py`) для предотвращения мерцания консольных окон.
  - Упаковка в автономные архивы:
    - `SS14.Launcher_Windows.zip` (Windows x64 + ARM64, `Space Station 14 Launcher.exe`, иконки, пакет батников)
    - `SS14.Launcher_Linux.tar.gz` (Linux x64 + ARM64, шелл-скрипт `SS14.Launcher`, `.desktop`-файл, иконка, скрипт установки)
  - Автоматический расчет контрольных сумм SHA-256 и генерация манифеста `SHA256SUMS.txt`.

### 3. Релизный конвейер GitHub Actions (`publish-release.yml`)
- **Триггер**: Создание и отправка тега формата `v*`.
- **Шлюз качества (Test Gate)**: Сборка релизных бинарников начинается **только** после 100% успешного прохождения автотестов на всех платформах.
- **Публикация**: Автоматическое прикрепление собранных архивов и контрольных сумм к странице GitHub Releases.

### 4. Комплекс безопасности и качества в GitHub
- **`codeql.yml`**: еженедельное статическое сканирование кода (SAST) на уязвимости (правила `security-extended` и `security-and-quality`).
- **`dependency-review.yml`**: блокировка PR при обнаружении уязвимостей высокой и критической степени в пакетах NuGet.
- **`dependabot.yml`**: автоматическое обновление зависимостей NuGet и GitHub Actions.

## ⚖️ Последствия и результаты

- **Результаты**:
  - Полная автоматизация подготовки кросс-платформенных релизов без ручного вмешательства.
  - Игроки получают готовый лаунчер со всеми зависимостями в один клик.
  - Надежный шлюз качества предотвращает попадание неработающего кода в релиз.
