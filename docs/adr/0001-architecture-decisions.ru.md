## 📋 Контекст и проблематика

Лаунчер **Space Station 14** является входной точкой для десятков тысяч игроков на платформах Windows, Linux и macOS. Ключевые требования к архитектуре:
1. **Мгновенный отклик интерфейса**: отсутствие зависаний UI при опросе сотен серверов, загрузке фонового видео и распаковке манифестов.
2. **Модульность и отсутствие God-объектов**: код бизнес-логики, алгоритмов и представления должен быть строго изолирован и доступен для модульного тестирования без моков GUI.
3. **Высокая производительность сетевой телеметрии**: сглаживание сетевого джиттера и фильтрация недостоверных всплесков пинга.
4. **Безопасная изоляция процесса игры**: передача управления клиенту игры с гарантией отсутствия утечек секретов хоста.

---

## 🎯 Принятые решения

### 1. Архитектурный паттерн MVVM на базе Avalonia UI
- **Решение**: Использовать **Avalonia UI 11** в сочетании с библиотекой **ReactiveUI** и `DynamicData`.
- **Обоснование**:
  - Кросс-платформенная поддержка с единым кодом XAML для Windows, Linux и macOS.
  - Рендеринг на базе Skia (Linux/macOS) и Direct3D/ANGLE (Windows).
  - Реактивные коллекции `IObservableCache<T, K>` и `SourceList<T>` для автоматической синхронизации списков серверов и избранного без блокировки UI-потока.
  - Разделение ответственности: Views занимаются только версткой и стилями, ViewModels — подготовкой данных и командами, Models — бизнес-логикой и хранилищем.

### 2. Декомпозиция монолитов на модули (`Utility.Algorithms`)
- **Решение**: Монолитный класс `AdvancedAlgorithms.cs` разделен на 10 специализированных классов в каталоге `Utility/Algorithms/`:
  - `Filters/KalmanLatencyTracker.cs`: 1D-фильтр Калмана с пороговым отсечением аномалий (Chi-squared gating, $p < 0.01$). Фильтрует шум TCP/UDP измерений и возвращает реалистичное значение задержки.
  - `Search/FastServerSearchIndex.cs`: многопоточный индекс префиксов и токенов на базе `ConcurrentDictionary` и закэшированных разделителей `TokenSeparators`.
  - `Search/SimdStringHelper.cs`: векторизованное приведение ASCII-строк к нижнему регистру через интринсики `Vector256<byte>` и `Vector128<byte>` с автоматическим скалярным фоллбэком.
  - `Search/StringMetrics.cs`: параллельное вычисление расстояния Майерса и Джаро-Винклера.
  - `Caching/HybridMemoryCache.cs`: потокобезопасный гибридный кэш с LRU-вытеснением при исчерпании лимита и TTL-инвалидацией устаревших записей.
  - `RateLimiting/TokenBucket.cs`: алгоритм корзины токенов для сглаживания запросов к хабам и защиты от блокировок.
  - `Statistics/RunningStatistics.cs`: инкрементальный расчет среднего и дисперсии по алгоритму Велфорда (Welford's algorithm) за $O(1)$ по памяти.
  - `Statistics/PSquareQuantileEstimator.cs`: динамическая оценка 95-го и 99-го перцентилей задержки по алгоритму P-Square без хранения выборки в памяти.
  - `Statistics/HoltLinearTrend.cs`: экспоненциальное прогнозирование тренда задержки и скорости передачи данных.
  - `Network/ThroughputEtaEstimator.cs`: адаптивный расчет оставшегося времени загрузки (ETA).
- Для обратной совместимости в `AdvancedAlgorithms.cs` сохранен фасад, делегирующий вызовы в новые модули.

### 3. Декомпозиция больших ViewModels (`DevelopmentTabViewModel`)
- **Решение**: Класс `DevelopmentTabViewModel.cs` разбит с помощью `partial class` на 3 файла:
  - `DevelopmentTabViewModel.cs`: объявление CVars, реактивных свойств и привязок к UI.
  - `DevelopmentTabViewModel.Diagnostics.cs`: бенчмаркинг алгоритмов, сбор системных метрик и диагностика сети.
  - `DevelopmentTabViewModel.Maintenance.cs`: функции очистки кэша контента, удаление старых движков, ротация логов и сброс настроек.

### 4. Изоляция игрового процесса через `GameProcessRunner`
- **Решение**: Логика конфигурирования, очистки переменных среды и запуска процесса вынесена из монолитного `Connector.cs` в выделенный класс `GameProcessRunner`.
- **Обоснование**: Гарантирует единую точку управления жизненным циклом процесса, исключает утечку системных токенов и упрощает перехват вывода консоли.

## ⚖️ Последствия и результаты

- **Плюсы**:
  - Полное устранение God-объектов в кодовой базе.
  - Покрытие модульными тестами всех алгоритмов (138 тестов со 100% успехом).
  - Снижение нагрузки на сборщик мусора (GC) в цикле поиска и фильтрации серверов.
  - Улучшение читаемости и сопровождаемости архитектуры новыми разработчиками.
- **Минусы**:
  - Увеличение числа файлов в проекте (компенсируется строгой иерархией каталогов).
