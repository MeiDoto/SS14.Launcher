## 🏛️ Обзор архитектуры проекта

Репозиторий состоит из нескольких взаимосвязанных проектов в одном решении .NET:

| Проект / Каталог | Описание и назначение |
|---|---|
| **`SS14.Launcher`** | Основное приложение. Построено на **Avalonia UI** с использованием паттерна **MVVM** (Model-View-ViewModel). Содержит интерфейс, логику кэширования, интеграцию с хабами, систему кастомизации тем и настройки CVars. |
| **`SS14.Loader`** | Внедряемый загрузчик (assembly loader). Отвечает за запуск сборок движка Robust Toolbox в изолированном контексте загрузки (AssemblyLoadContext) без конфликтов зависимостей. |
| **`Robust.LoaderApi`** | Легковесный API-контракт между лаунчером и загрузчиком движка. |
| **`SS14.Launcher.Bootstrap`** | Нативная точка входа под Windows (C++). Корректно настраивает флаги Win32-подсистем (GUI/Console), предотвращая ложное мерцание консоли и обеспечивая плавный старт. |
| **`SS14.Launcher.Tests`** | Набор модульных тестов на базе **NUnit** (138 тестов). Покрывает алгоритмы фильтрации, кэш, сетевую защиту, парсинг ссылок и целостность данных. |
| **`SS14.Launcher/Utility/Algorithms/`** | Модульный набор высокопроизводительных алгоритмов: SIMD-поиск (`Search/`), сглаживание пинга фильтром Калмана (`Filters/`), гибридный LRU+TTL кэш (`Caching/`), оценка трендов и квантилей (`Statistics/`), рейтограничение Token Bucket (`RateLimiting/`). |

## 🔄 Внутренние механизмы (Data Flow)

### 1. Авторизация и аккаунты (`Models/Logins/`)
- Лаунчер взаимодействует с сервером авторизации Space Station 14 по безопасному протоколу HTTPS.
- Токены сессии защищаются шифрованием. Периодический фоновый таймер обновляет токены до истечения их срока жизни (`TokenRefreshInterval`).
- Поддерживается двухфакторная аутентификация (2FA) и мульти-аккаунтность.

### 2. Обнаружение серверов и сетевая телеметрия (`Models/ServerStatus/`)
- Списки серверов параллельно запрашиваются из центрального хаба и пользовательских хабов.
- Для предотвращения задержек на IPv6/IPv4 используется реализация алгоритма **Happy Eyeballs**.
- Значения сетевой задержки (ping) фильтруются 1D-фильтром Калмана с отсечением аномальных всплесков (Chi-squared gating), что дает стабильное и реалистичное отображение пинга в списке серверов.
- Поиск серверов по тексту ускоряется индексом токенов с SIMD-инструкциями (Vector256 / Vector128).

### 3. Загрузка контента и версий движка (`Models/ContentManagement/`, `Models/EngineManager/`)
- При подключении к серверу лаунчер запрашивает манифест версии движка и серверного контента.
- Недостающие версии движка скачиваются с Robust CDN.
- Контент сервера упакован в формате сжатия zstd/brotli и кэшируется в базе данных **SQLite** в режиме **WAL** (Write-Ahead Logging), что позволяет скачивать фоновые обновления без блокировки работающего клиента игры.

### 4. Изоляция и запуск игрового процесса (`Utility/GameProcessRunner.cs`)
- Запуск игры изолирует переменные окружения, исключая утечку конфиденциальных данных.
- Автоматически выставляются переменные дискретной графики под Linux (`DRI_PRIME=1`, `__NV_PRIME_RENDER_OFFLOAD=1`, `__GLX_VENDOR_LIBRARY_NAME=nvidia`).
- Процесс запускается с повышенным приоритетом для снижения задержек ввода при включенной опции в настройках.

## 💻 Настройка окружения разработчика

### Предварительные требования
- **[.NET 10.0 SDK](https://dotnet.microsoft.com/download)** (или новее)
- **Git**
- Рекомендуемые среды разработки: **JetBrains Rider**, **Visual Studio 2022+** (с поддержкой .NET 10) или **VS Code** с расширением C# Dev Kit.

### Клонирование и сборка

```bash
# Клонирование с рекурсивной загрузкой всех подмодулей
git clone --recursive https://github.com/MeiDoto/SS14.Launcher.git
cd SS14.Launcher

# Сборка проекта
dotnet build -c Release -p:UseSharedCompilation=false

# Запуск тестов
dotnet test SS14.Launcher.Tests/SS14.Launcher.Tests.csproj -p:UseSharedCompilation=false
```

### Запуск в режиме разработки
Для изоляции настроек от установленного в системе лаунчера используйте флаг `--launcher-data-dir`:

```bash
dotnet run --project SS14.Launcher -- --launcher-data-dir ./dev-userdata
```

## 🎯 Стандарты качества кода

Мы поддерживаем планку качества **10/10** — в проекте включен режим нулевой терпимости к предупреждениям компилятора:

### 1. Асинхронное программирование (Async Safety)
- Все публичные асинхронные методы **обязаны** возвращать `Task` или `Task<T>`.
- Использование `async void` **строго запрещено** везде, кроме прямых обработчиков событий Avalonia UI (`RoutedEventArgs`).
- Для запуска фоновых задач без ожидания (fire-and-forget) **обязательно** используйте оператор сброса результата:
  ```csharp
  // ПРАВИЛЬНО:
  _ = CommitConfig();
  _ = BackgroundWorkerAsync();

  // НЕПРАВИЛЬНО (вызывает предупреждение CS4014):
  CommitConfig();
  ```
- Внутри любых фоновых методов обязательно оборачивайте выполнение в блок `try/catch` с логированием, чтобы необработанное исключение не привело к аварийному завершению приложения.

### 2. Обработка ошибок (Error Handling)
- **Никаких пустых блоков `catch { }`!**
- Все перехваченные исключения должны быть типизированы и залогированы через `Serilog`:
  ```csharp
  try
  {
      PerformOperation();
  }
  catch (Exception ex)
  {
      Log.Warning(ex, "Не удалось выполнить операцию для {Entity}", entityId);
  }
  ```
- Если исключение намеренно игнорируется в безопасной ветке отката, используйте `catch (Exception)` без объявления неиспользуемой переменной (во избежание CS0168), сопроводив комментарием или `Log.Debug`.

### 3. Производительность и управление памятью
- При парсинге строк и операциях поиска предпочитайте `ReadOnlySpan<char>` и статические кэшированные разделители вместо частых вызовов `string.Split()`.
- Для промежуточных бинарных буферов используйте `ArrayPool<byte>.Shared`.
- В критичных по скорости алгоритмах избегайте создания объектов исключений для управления потоком выполнения — применяйте паттерн `ValueResult<T>`.

## 🌐 Руководство по локализации (i18n)

Лаунчер полностью интернационализирован с использованием системы **Project Fluent**.

Файлы переводов находятся в папке:
- `SS14.Launcher/Assets/Locale/en-US/text.ftl` (Английский — эталон)
- `SS14.Launcher/Assets/Locale/ru/text.ftl` (Русский перевод)

### Правила добавления строк:
1. **Никакого хардкода текста в XAML или C#!** Любая строка в интерфейсе должна ссылаться на ключ локализации.
2. В XAML используйте разметку:
   ```xml
   <TextBlock Text="{Loc my-feature-title}" />
   ```
3. В C# ViewModel используйте менеджер локализации:
   ```csharp
   var text = LocalizationManager.Instance.GetString("my-feature-status", ("count", count));
   ```
4. В `.ftl` файлах объявляйте перевод для обоих языков:
   ```fluent
   # en-US/text.ftl
   my-feature-title = Advanced Diagnostics
   my-feature-status = Processed { $count } items successfully.

   # ru/text.ftl
   my-feature-title = Расширенная диагностика
   my-feature-status = Успешно обработано элементов: { $count }.
   ```

## 🚀 Процесс отправки Pull Request

1. Сделайте форк репозитория и создайте ветку с понятным названием (`feature/awesome-filter` или `fix/network-timeout`).
2. Внесите изменения, придерживаясь стандартов кода и добавив тесты для новой функциональности.
3. Убедитесь, что `dotnet test` возвращает 100% успех.
4. Создайте Pull Request в ветку `master`. Заполните шаблон PR, отметив все пункты чеклиста качества.
